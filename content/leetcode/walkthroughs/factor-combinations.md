## Intuition
A factor combination can be generated by choosing factors in nondecreasing order.
Once a factor is chosen, the remaining quotient becomes the smaller subproblem, and trying only factors up to its square root avoids duplicate pairs.
Appending the quotient creates the final two-factor combination at each divisible choice.

## Brute force
Trying every sequence of integers greater than one and checking its product creates many permutations and invalid partial products.
The ordered backtracking state eliminates both by enforcing a smallest allowed factor and dividing only when a factor fits.

## Approach
1. Start with remaining value `n`, smallest factor 2, and an empty path.
2. Try each factor from the smallest allowed value through `sqrt(remaining)`.
3. When it divides the remainder, add the path plus the factor and quotient as one result.
4. Recurse on the quotient with the same factor as the new lower bound.
5. Keep branches independent: Java removes its appended factor on return, while Python passes a fresh extended path.

## Walkthrough
Example 1 uses `n = 12`.
Choosing factor 2 adds `[2, 6]`.
Recursing on 6 with lower bound 2 chooses another 2 and adds `[2, 2, 3]`.
Returning to the top level, factor 3 adds `[3, 4]`.
The lower-bound rule prevents reversed duplicates such as `[6, 2]`.

## Complexity
The search time is proportional to the divisor states explored and their trial factors, plus the cost of copying each returned combination.
The recursion depth is O(log n) for repeated factor 2, and live path-copy allocations along that stack can total O(log squared n).
Stored output requires additional space proportional to the returned combinations.

## Edge cases
Values below four have no product of at least two factors.
A prime has no divisible trial factor and returns an empty list.
Repeated factors such as `[2, 2, 2]` are allowed because the order remains nondecreasing.

## Common mistakes
Allowing factors below the previous choice creates duplicate permutations.
Returning the remaining value alone incorrectly treats `n` as a one-factor combination.
Continuing trial factors beyond the square root duplicates the complementary pair.

## Language notes
Python uses `math.isqrt` for an exact integer square-root bound.
Java uses `factor * factor <= remaining`, safe because the input is at most ten million.
Java mutates and restores one backtracking path, using O(log n) stack and path space beyond its output.
Python copies the extended path for each recursive call, giving the O(log squared n) live-copy bound above.
Both copy completed combinations into the result.
